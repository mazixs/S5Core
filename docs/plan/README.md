# Материалы плана работ

Шесть автономных HTML: открываются без интернета, ничего не тянут из сети.
Это записи своего времени, а не описание текущего кода - код описывают
[`../veil-spec.md`](../veil-spec.md), [`../design/`](../design/) и README
репозитория. Пути к документам внутри них приведены к нынешней раскладке
каталога.

Порядок, в котором они писались, он же порядок чтения:

1. [`audit.html`](audit.html) (18.09.2026) - технический аудит кодовой базы и
   разбор боевого багрепорта. Отсюда взялся список проблем.
2. [`blockers.html`](blockers.html) (18.09.2026) - 29 блокеров и слепых зон:
   что мешает и чего мы не знаем.
3. [`research.html`](research.html) (18.09.2026) - RnD-исследование по этим
   блокерам: гипотезы и практика рынка.
4. [`plan.html`](plan.html) (18.09.2026) - план реализации: фазы Ф0-Ф6 и пять
   шлюзов. Номера задач (Ф5-1, Ф6-3 и так далее), которыми размечены
   документы и комментарии в коде, - отсюда.
5. [`dpi-research.html`](dpi-research.html) (19.09.2026) - отдельное
   исследование направлений обхода DPI, написанное уже по ходу фазы 5.
6. [`result.html`](result.html) (20.09.2026) - итог выполнения плана: что
   сделано, чем проверено, какие числа получены.

Рядом с ними лежат рабочие планы открытой работы (Markdown): решения с
причинами, открытые вопросы и задачи, которые обновляются по ходу работы, а не
фиксируют прошлое состояние. Сейчас это [`mips.md`](mips.md) - клиент под
MIPS-роутеры, и [`gaming.md`](gaming.md) - долгие игровые сессии через туннель.

Вердикты шлюзов живут не здесь, а в [`../gates/`](../gates/): шлюз - решение,
и оно опирается на замер, который со временем повторяют.
