## Контракты и настройки

- Старый NameResolver продолжает работать с одним адресом. ResolveAll добавляет возможность передать набор. Автоматического DNS-кеша нет.
- Rules проверяется до DNS, затем для каждого кандидата встроенного или многозначного resolver. Dial получает проверенный числовой адрес, без повторного разрешения имени.
- При настроенном Rewriter его единственный результат остается окончательным: fallback к адресам до переписывания отключен. Это сохраняет адресную политику существующего интерфейса.
- uTLS использует NetDialTLSContext; URL остается wss, включая правильный порт по умолчанию. TLS fingerprint требует wss URL. Проверка сертификатов и pinning сохранены.
- В метриках появился дополнительный ограниченный label phase=dns. first_byte остается первым TCP-байтом назначения; для HTTPS это обычно TLS, а не HTTP-ответ. Гистограммы не обещают полное разложение HTTP-задержки.

## Исправление R01 после независимого ревью

[Независимое ревью](socks5-https-remediation-review-2026-09-21.md) обнаружило регрессию в распределении бюджета H03: при 16 адресах и бюджете 10s первый адрес получал только 625ms. Предыдущий зеленый набор проверок этот сценарий не покрывал.

Доля попытки теперь имеет минимум 2s, ограниченный оставшимся общим временем, по принципу net.partialDeadline из Go 1.26.6. Задержка запуска fallback остается отдельной настройкой алгоритма. Дополнительно запрещен запуск новых кандидатов после истечения общего срока, включая момент, когда deadline дочерней попытки уже сработал, а отмена родителя еще не обработана.

| Приемка | До исправления | После исправления |
| --- | --- | --- |
| 16 адресов, бюджет 10s, первый рабочий за 1s | Отказ через 625ms | Успех за 1s |
| 64 смешанных адреса, бюджет 10s, первый рабочий за 1.5s | Отказ через 156.25ms | Успех за 1.5s |
| 16 адресов, бюджет 1s, первый рабочий за 750ms | Отказ через 62.5ms | Успех за 750ms |

В каждом сценарии остальные адреса быстро отказывают. Проверяются максимум две одновременные попытки и отсутствие оставшихся активных вызовов. Тесты общего срока теперь отдельно проверяют четыре зависших адреса при достаточном бюджете 10s и завершение за 1s без запуска оставшихся адресов при коротком бюджете. Приоритетом остается доступность начатой попытки в разумном интервале; полный перебор при любом коротком бюджете не обещается.

Все числа в этой таблице получены через testing/synctest и управляемый Dial, а не измерением внешнего RTT. Фикстура ревью и сам отчет ревью сохранены без изменений. Новые приемочные тесты проверяют успешное подключение и до исправления падали.

## Как проверить рабочий маршрут

```bash
go run ./cmd/httpsprobe -url https://example.com/ -count 3 -timeout 45s
go run ./cmd/httpsprobe -url https://example.com/ -socks 127.0.0.1:1080 -count 3 -timeout 45s
go run ./cmd/httpsprobe -url https://example.com/ -socks 127.0.0.1:1080 -count 3 -reuse -http2=true
```

Для obfs/WSS параметр socks указывает на локальный s5client. Зонд проверяет сертификаты, не следует redirect, выводит JSON со временем setup, TLS, первым HTTP-байтом, полным чтением, протоколом, reuse, размером и SHA-256. Поддерживается дополнительный CA через -ca. Неполное тело дает ошибку, число фактически прочитанных байт и ненулевой код выхода.

Рабочие серверы, потери пакетов, реальный IPv6 blackhole и внешние маршруты не проверялись. Зависшие попытки моделировались через отменяемый Dial, а реальный DNS fallback проверялся на loopback. Выбор нового шифра, DNS-кеша и настройка производственных серверов не входили в эти исправления.
