# Падение CI на записи первого obfs-соединения

Проверен запуск [35619028213](https://github.com/mazixs/S5Core/actions/runs/35619028213)
для коммита `112a930afc67e026632aa89772b28cd65f95b331`.
Рабочее дерево перед исправлениями чистое. Старые предупреждения Node.js и
Ubuntu в этом запуске отсутствуют.

## Подтвержденная причина

`TestAReplayedFirstFlightIsAnsweredLikeGarbage` давал серверу 500 мс на весь
handshake, включая запись заведомо рабочего соединения перед replay-пробами.
Тест создает учетную запись с открытым паролем. `CredentialAdapter.Valid`
синхронно вызывает `Store.MigratePassword`: Argon2id и сохранение файла идут
до отправки успешного ответа аутентификации.

Цепочка сбоя:

1. `listenerPipeline.Accept` фиксирует абсолютный handshake-бюджет сессии.
2. `UserPassAuthenticator.Authenticate` проверяет пароль и ждет миграцию.
3. `timeoutConn.Write` ставит уже истекший deadline на запись ответа.
4. Запись возвращает timeout; обработчик закрывает соединение.
5. Клиент видит только `auth read: EOF`. Это не доказательство отказа паролю
   или ошибки replay-защиты: replay-пробы еще не начались.

Исходный тест прошел три раза без ограничения CPU. Тот же бинарь с `-race`
в контейнере `golang:1.26.6` с `--cpus=0.25` воспроизвел исходный EOF.
После добавления диагностики тот же сценарий показал:

```text
stage=auth operation=result_write kind=timeout transport=obfs
protocol_state=handshake handshake_budget=500ms elapsed=703.399799ms
```

Исправление: запись рабочего соединения использует `DefaultHandshakeTimeout`
(15 секунд), затем `UpdateHandshakeTimeout(500*time.Millisecond)` задает
исходный короткий бюджет только новым replay/garbage-пробам. История солей
остается на том же сервере. Число проб, требования тишины и пороги сравнения
не ослаблены. Исправленный тест прошел три раза с тем же ограничением CPU.
Производственные таймауты и синхронная миграция паролей не изменены.

## Второй нестабильный тест

Полный прогон выявил `TestTheConnectionLimitCoversTheObfuscatedPort`:
`pipeline_test.go:73: connection 1 handshake: EOF`. Общий `waitForPort`
проверял только успешный TCP dial и сразу закрывал клиентский сокет.
К этому моменту сервер мог еще держать оба слота готовности (plain и obfs),
поэтому первая настоящая сессия попадала под `MAX_CONNECTIONS=2`.

Теперь readiness-проба делает TCP half-close и ждет EOF со стороны сервера.
Закрытие серверного wrapper освобождает слот до закрытия сокета, поэтому
готовность больше не обгоняет очистку probe-соединения. Добавлен тест с
управляемым закрытием серверной стороны. Лимит соединений не увеличен.

## Подтвержденные дефекты диагностики

- Сервер возвращал неструктурированные ошибки; клиентский EOF не позволял
  определить серверный этап и причину. В тестах debug-лог был выключен.
- При ошибке DNS/подключения последующая ошибка отправки SOCKS-ответа
  заменяла исходную. Теперь обе причины сохраняются через `errors.Join`.
  Аналогично сохранен отказ аутентификации/правил при неудачной записи ответа.
- CI выводил общую annotation с кодом завершения скрипта без имени теста
  и ссылки на строку его падения.

`ConnError` теперь содержит `Stage`, `Op`, `Kind` и исходную ошибку через
`Unwrap`. Проверки `errors.Is` и `errors.As`, включая `net.Error.Timeout`,
сохраняют смысл. Классы: `timeout`, `peer_closed`, `canceled`,
`auth_rejected`, `protocol_invalid`, `policy_rejected`, `network`, `internal`.
Существующая классификация obfs сохраняется в `protocol_reason`.

Одна debug-запись содержит этап, операцию, класс, транспорт, состояние,
handshake-бюджет, время обработки и коды всех объединенных причин. Сырые
сетевые ошибки, адреса и учетные данные в новую запись не попадают.
В production используется существующий временный режим `LOG_LEVEL=debug`;
общий helper интеграционных тестов включает его и привязывает записи к тесту.

## Отчеты CI

`scripts/pre-commit.sh` запускает тесты с `-json`, сохраняет полный поток в
`.ci-reports/tests.jsonl`, stderr в `.ci-reports/tests.stderr.log` и передает
события в `scripts/testreport`. Успешные тесты не печатают подробные логи.

Для падений создаются annotations с пакетом, тестом, исходным файлом/строкой
и последними диагностическими сообщениями. Классы отчета: `test_failure`,
`data_race`, `panic`, `build_failure`, `package_failure`. Они обозначают вид
сбоя проверки; серверная причина остается отдельными полями `stage/op/kind`.
Ошибки остальных проверок получают название этапа. Ошибки установки
инструментов и упавших бенчмарков больше не подавляются перенаправлением. `pipefail` сохраняет
неуспешный статус тестов, записи артефакта и генератора отчета.

CI и release-checks загружают coverage и диагностические файлы даже при
падении. Каталог `.ci-reports` исключен из Git как результат проверок.

## Проверка

- Детерминированный тест на `net.Pipe` и `synctest`: правильные credentials
  завершаются после бюджета; клиент получает EOF, сервер - классифицированный
  `auth/result_write/timeout` с сохраненным `net.Error`.
- Проверки чтения auth-пакетов, неверного пароля, версии, закрытия сокета,
  отмены, timeout и сохранения двух причин при неудачном ответе.
- Генератор отчета проверен на JSON настоящего воспроизведенного падения:
  annotation указывает на `replay_probe_test.go:177`, а не на cleanup-лог.
- Проверены события ошибки компиляции Go (`ImportPath`/`FailedBuild`),
  panic-стек, race-классификация, экранирование annotations и поврежденный JSON.

Финальный `./scripts/pre-commit.sh` прошел полностью: gofmt, проверка символов,
`go mod verify`, `go mod tidy -diff`, vet, golangci-lint (0 замечаний),
govulncheck (0 вызываемых уязвимостей), все race-тесты с coverage, бенчмарки
и сборка обоих бинарей. `actionlint` и `bash -n` прошли.
Тест лимита соединений и новый тест readiness прошли 30 повторов с `-race`.

Изменения локальные. Окончательное подтверждение на GitHub требует нового
запуска после публикации.
