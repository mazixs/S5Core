# Внешние исследования

Этот каталог - обзоры внешних источников: стандартов, документации вендоров и операторов, опубликованных замеров и разборов инцидентов. Код S5Core эти документы не измеряют и не проверяют. Собственные замеры проекта лежат в [`../benchmarks/`](../benchmarks/) и [`../field/`](../field/). Выводы для проекта здесь сформулированы как вопросы для проверки, а не как установленные факты.

| Документ | О чем |
| --- | --- |
| [`mtu.md`](mtu.md) | Зачем нужен MTU. Где на пути от устройства до сервера теряются байты (провайдер, роутер, мобильная сеть, облако, VPN, прокси). Что будет с пакетом, который не влез: "1520 вместо 1500". Статистика отказов PMTUD и фрагментации, инциденты, рекомендации. Раздел 10 - что это значит для S5Core |
| [`mtu-diagnostics.md`](mtu-diagnostics.md) | Как MTU ведут себя Linux, Windows, macOS, FreeBSD, Android, роутеры, Go и quic-go. Команды и счетчики. Пошаговая методика клиент - роутер - провайдер - сервер. Стенд без root |
| [`path-degradation.md`](path-degradation.md) | Что портит связь помимо MTU: bufferbloat, потери и джиттер, TCP поверх TCP, полисинг и DPI, NAT, ECN и DSCP, Wi-Fi, LTE и спутник, хост и роутер, ловушки измерений. Таблица "симптом - причина - проверка" |
| [`dial-dual-stack.md`](dial-dual-stack.md) | Исходящий dial по имени: RFC 8305 и черновик HEv3, выбор адреса по RFC 6724, поведение Go, curl, Chromium, Envoy и других при A+AAAA без IPv6, запасные сокеты против глухих портов ECMP, коды ответа SOCKS5. Раздел 5 - решение для S5Core |
| [`logging.md`](logging.md) | Логи и наблюдаемость прокси: итоговая строка на соединение, корреляция сторон, разделение по аккаунтам и приватность, цена slog (замер), буферы и ротация. Раздел 3 - дизайн журнала сессий для S5Core |

## Метод

- Дата сбора - 26.09.2026. Источники этого года и более ранние указаны с датами.
- Классы источников: RFC и стандарты (IEEE, 3GPP, BBF, CableLabs), официальная документация вендоров, операторов и облаков, исходники (Linux, XNU, FreeBSD, Go, quic-go, WireGuard, прокси-ядра), рецензируемые и инженерные замеры (IMC, TMA, SIGCOMM, RIPE Labs, APNIC, Cloudflare), разборы инцидентов и issue на GitHub.
- Пометки в тексте:
  - [не подтверждено] - первоисточник не найден или прочитан только в выдаче поиска;
  - [расчет] - арифметика по числам источника;
  - [вывод] - заключение авторов обзора, которого нет в источнике;
  - [лаб] - проверено опытом в сетевых пространствах Linux без root (стенд - в разделе 7 `mtu-diagnostics.md`).
- Номера источников свои в каждом документе.

## Обновление

- Числа провайдеров, облаков и стеков меняются: перед тем как опираться на значение по умолчанию, проверьте его по ссылке.
- Свежие замеры добавляйте с датой и методом, старые не удаляйте: разница между годами тоже результат.
- Собственные замеры S5Core сюда не попадают, их место - `../benchmarks/` или `../field/`.
