# План 2.3 rc6

Рабочий план от 01.10.2026. rc5 работает на узлах A-D с 29.09.2026 19:18 UTC.
Разбор суточной сессии через DE2 (YouTube иногда долго показывал черный экран,
в Discord были обрывы WebSocket) нашел дефект dial у имен с несколькими
адресами и показал, что по серверным логам нельзя классифицировать работу
сервиса. rc6 - сборка с двумя направлениями: единое расписание dial и
журнал сессий с итоговыми строками на сервере и на клиенте.

## Факты

- DE2: часть адресов Google по IPv4 глохнет детерминированно по исходящему
  порту (172.217.132.72:443 - 19-33% портов), UDP к 8.8.8.8:53 - 34%. На DE1
  тех же адресов 0 глухих, Cloudflare, Discord, Telegram, GitHub и Google по
  IPv6 чисты. Дыра в сети хостера или Google, локализация не доказана
  (Ч-26 в [`draft.md`](draft.md)).
- Имя с A и AAAA на IPv4-only контейнере уходит в гонку `dialResolved`: AAAA
  падает сразу, IPv4 получает долю бюджета 5 с и ни одного запасного сокета.
  Попадание в глухой порт - отказ с кодом 4 через 5,1 с (40% на имени, 60
  попыток). По литералу запасные работают: 80 из 80, p90 1,6 с. Full tunnel
  ходит по литералам, поэтому его этот дефект не задевает; задевает клиентов с
  удаленным DNS.
- Логи: клиентский лог затирался при перезапуске (исправлено в шаблонах
  `bench/clients`, архив `logs/archive/`, 40 запусков); серверный INFO
  содержал только строки ротации UDP-сокета; в отказе dial и ротации нет
  сети назначения; клиентский обрыв нельзя связать с серверной сессией.
- DNS DE2 заменен на 9.9.9.9 и 1.1.1.1 (бэкап `/etc/resolv.conf.bak-20261001`);
  запущенный контейнер держит прежние резолверы до перезапуска, то есть до
  выкладки rc6. Второй резолвер хостера по замеру не отвечает.
- Три независимых прохода (основной и два ревьюера) сошлись на дефекте dial и
  на том, что IPv6 для контейнера не лечит full tunnel. Обрывы Discord
  16:03-16:07 МСК не объяснены, нужны клиентские логи (теперь сохраняются).

## Решения

- **Dial: одно расписание для имени, как для литерала**
  ([`../research/dial-dual-stack.md`](../research/dial-dual-stack.md)).
  Гонка адресов с шагом 250 мс (не меньше 10 мс), у каждого ждущего адреса свои
  запасные сокеты по `backupAfter`, общий предел 6 сокетов на CONNECT, локальные
  отказы (`ENETUNREACH`, `EAFNOSUPPORT`) в предел не входят. Доля бюджета и
  правило "не больше двух попыток" убираются. Имя с одним живым адресом ведет
  себя как литерал. Проба маршрута и настройка семейства отклонены. Литерал
  по поведению не меняется: отдельной `dialOne` больше нет, один адрес идет
  через то же расписание.
- **Журнал сессий вместо россыпи строк**
  ([`../research/logging.md`](../research/logging.md)). Служебный лог в stdout
  остается без аккаунтов и адресов. Рядом отдельный файл JSONL (`SESSION_LOG`),
  по строке `conn_end` и `assoc_end` на соединение и ассоциацию: аккаунт, сеть
  назначения /24 или /48, исход из закрытого списка, кто закрыл, фазы, попытки
  dial и запасные сокеты, байты, длительность. Один файл с полем `account`, а
  не файл на аккаунт.
- **Исключение из политики наблюдаемости.** Владелец потребовал разделять логи
  по аккаунтам, поэтому `docs/design/observability-policy.md` получает
  исключение для журнала сессий: имя аккаунта и сеть назначения допустимы
  в нем и недопустимы в метриках и служебном логе. Ключи, пароли и имена
  неудачных логинов не пишутся никогда.
- **Номер соединения без изменения провода.** 48 бит, выводятся обеими
  сторонами из секрета сессии с отдельной меткой HKDF. Сервер печатает его для
  клиентов 2.2 и 2.3, клиент печатает с rc6.
- **Горячий путь.** Журнал пишется буферизованно (64 КиБ), без `With` на
  соединение, без горутины-писателя с каналом (на одном ядре терял 65-71%
  строк при всплеске). Строка из 16 полей - 1,6 мкс и 1 аллокация. Запись
  вне горячего пути кадров: только на границах соединения.
- **Правила выкладки.** Сначала тестовая сборка на узле, rc - по решению
  пользователя. Тег и релиз только по команде. Коммит и push - по команде.

## Открытые вопросы

- Причина обрывов Discord 16:03-16:07 и двухминутного сбоя gateway в
  15:32-15:34 (30.09.2026).
- Дыра Google на DE2: тикет хостеру (текст готов), смена IP.
- Чистка и рефакторинг по аудиту: решение 01.10.2026 - все в rc6, включая сложные функции и `pkg/*` (с сохранением совместимости API: алиасы вместо удаления).
