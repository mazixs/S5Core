# Три дополнительных исправления по аудиту 05.10.2026

Два P2 и один P3 воспроизведены и исправлены локально после
[предыдущих доработок](code-audit-fixes-2026-10-05.md). Этот отчет относится
к новым исходникам, а не к уже установленной сборке RC3. Работающие узлы
и клиентские пакеты в рамках этих исправлений не обновлялись.

## P2: замена владельца имени

До исправления существующий CONNECT оставался открытым после замены
аккаунта с сохранением имени. Это воспроизведено для входа по паролю и
ключу участника. Сохраненный Admin получил права новой записи.

Теперь при аутентификации фиксируется экземпляр аккаунта. Проверка доступа,
идентичность и счетчик трафика относятся к одной записи. Обычный Reload
с сохранением ID обновляет ее политику; замена ID, удаление с повторным
созданием и переименование отзывают старую привязку. Пересоздание того же
ID после удаления не оживляет прежнюю сессию или Admin.

Каталог ключей хранит ссылку на экземпляр записи. Устаревший каталог
не может перенести результат проверки старого ключа на нового владельца
имени. Привязка пароля выбирается до проверки учетных данных, поэтому
замена аккаунта во время этой проверки также отвергается. Это локальные
метаданные сервера: формат обмена и ключи протокола не меняются.

Критерии локальной приемки:

- [x] Старый CONNECT прекращается после замены как при входе по паролю,
  так и по ключу участника; чтение заканчивается, а не только достигает таймаута.
- [x] Старые ассоциации RFC UDP, UDP через TCP и native UDP прекращаются
  на предусмотренной границе проверки политики.
- [x] Новая запись с квотой 1 байт не получает расход старой сессии;
  ее собственная квота применяется. Отдельно проверена запись 128 КиБ
  в старый счетчик после замены.
- [x] Старый Admin больше не читает Actor, не получает права новой записи
  и не выполняет административную операцию; свежий Admin работает.
- [x] Проверены удаление/создание с тем же ID, переименование, смена роли
  при обычном Reload, замена во время проверки пароля и устаревший каталог ключей.

TCP сохраняет периодический опрос раз в секунду и заданный бюджет
завершения сессии. UDP сохраняет проверку на границе 64 КиБ либо при первом
прикладном пакете после секунды. Молчащая UDP-ассоциация не создает
самостоятельный трафик для такой проверки. Немедленный запрет каждого
отдельного пакета после Reload этим контрактом не обещается; оставшийся
расход не относится к квоте нового владельца.

Проверки: [userstore](../../internal/userstore/binding_test.go),
[граница аутентификации](../../internal/socks5/account_binding_test.go),
[настоящие CONNECT и три режима UDP](../../pkg/s5server/review_followup_test.go).

## P2: ограничения после повторного Start

До исправления три запуска одного Server показали возврат таймаутов
7/8 секунд к 30/30 и разрешение ранее запрещенного localhost.

Последние корректные значения UpdateWhitelist, UpdateTimeouts,
UpdateHandshakeTimeout и UpdateSessionTimeouts теперь хранятся на Server.
Создаваемый слушатель получает их под той же блокировкой, что и обновление,
до начала обслуживания. Начальная конфигурация остается неизменяемой.

- [x] Три цикла Start/Stop сохраняют запрет localhost и все шесть бюджетов:
  чтение, запись, handshake, dial, тело кадра и завершение по квоте.
- [x] Обновление до первого Start и во время запуска доходит до каждого
  из трех слушателей: plain TCP, obfs и TLS WebSocket. Проверены два цикла.
- [x] Проверки проходят с детектором гонок; существующие сессии сохраняют
  бюджеты, зафиксированные при их принятии.

Это исправление SDK при повторном использовании объекта Server.
Перезапуск процесса с чтением конфигурации не является исходным сценарием.

## P3: конкурентное чтение Boot

До исправления детектор гонок сообщил о конфликте между Boot и Start.
Идентификатор теперь читается и записывается атомарно. Каждый принятый
Start создает новый идентификатор запуска; Stop оставляет последний.
До первого Start доступен предварительный идентификатор NewServer.
Отклоненный одновременный Start его не меняет; неудавшийся принятый запуск
также имеет собственный идентификатор.

- [x] Конкурентное чтение Boot при десяти циклах Start/Stop проходит
  с `-race`; идентификатор меняется на Start и сохраняется после Stop.
- [x] Контракт привязок, runtime-настроек и Boot описан в
  [руководстве SDK](../guides/sdk.md).
