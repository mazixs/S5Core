# Native UDP: короткий игровой стенд 25.09.2026

Команда: `python3 scripts/matrix/matrix.py run scripts/matrix/plans/game-native-smoke.toml`.
Локальный Linux amd64, `netem` на плече клиент-сервер: RTT 50 мс, случайные
потери 0,5% для TCP и native UDP. Поток: 64 тика/с, 200 байт, 30 секунд.
Варианты шли одновременно с прямым контролем. Источник чисел - сохраненные
[результаты обеих серий](data-2026-09-25/nativeudp-smoke-2026-09-25.json), извлеченные из
`result.json` в `bench/runs/`; полный отчет
`bench/runs/game-native-smoke-20260925-010728/report.html` - локальные данные,
не в репозитории.

| Путь | Ответов из 1920 | p50, мс | p99, мс | Потерянные тики, % | Замирания |
|---|---:|---:|---:|---:|---:|
| Напрямую | 1907 | 50,070 | 50,147 | 0,677 | 0 |
| `0x83` через obfs | 1920 | 50,259 | 102,685 | 0 | 0 |
| Native UDP через obfs | 1899 | 50,251 | 50,393 | 1,094 | 0 |

В `client.log` native-ячейки есть записи `Native UDP verified for association`
и `Native UDP carrying application datagrams`. Все три ячейки завершились
со статусом `ok`. Две пометки отчета `WARN 1` - ожидаемое предупреждение
тестового сервера о выключенной аутентификации в вариантах `0x83` и native.

Предыдущая такая же короткая серия (`game-native-smoke-20260925-010524`)
дала p99 50,204 мс напрямую, 103,935 мс через `0x83` и 50,425 мс через
native UDP; потери тиков - 0,990%, 0% и 1,198% соответственно. Колебание
доли потерь на 1920 тиках показывает, почему короткая серия не заменяет
полный `game-loss`.

Локальный бенчмарк `BenchmarkCodecRoundTrip` для 200 байт на этой машине:
1921 нс/цикл, 0 Б и 0 аллокаций на цикл. Это только шифрование и разбор
в памяти, без сокетов и планировщика. WAN, ARM/MIPS, фильтрующий путь,
мобильная сеть и игровое приложение здесь не проверялись. Пороги приемки
2.3 по полному `game-loss` и полю остаются открытыми.
